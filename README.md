# VOID LEADS v0.8.0 — Company Hunter

**Новая версия:** кроме рекламы, VOID LEADS теперь собирает сведения о бизнесах из разрешённых источников, проверяет HTML главных страниц и подготавливает персональные гипотезы для разговора с клиентом.

## Быстрый запуск поиска

1. Обнови приложение в **Настройки → Проверить обновления** (Windows).
2. Открой раздел **Company Hunter**. На первом запуске существующие CRM-карточки, заметки и статусы сохраняются.
3. Поиск **Wikidata** можно запустить одной кнопкой или включить еженедельное автоматическое обновление. Это открытые данные, но неполный справочник.
4. Поиск **VK-сообществ** требует *пользовательский токен VK с доступом к groups.search*. Сервисный токен от Public Hunter не подходит. Получи user-token через официальную авторизацию своего приложения VK; добавь его в Company Hunter. Он сохраняется только на Windows в защищённом DPAPI-файле отдельно от сервисного. **Не вводи пароль VK и не отправляй токен в чат.** После этого нажми **«Запустить все 9 направлений»** либо включи поиск раз в сутки: Рязань, Тула, Калуга × мебель, строительство, производство.
5. Для дополнительного поиска загрузить локальную городскую выгрузку **OSM GeoJSON**, содержащую OSM ID объектов; список российских компаний здесь не полный, результаты требуют проверки.
6. Включи **автоаудит до 8 сайтов в сутки** или запусти пакет вручную. Компаниям ничего автоматически не отправляется.
7. Для рекламных постов оставлен **Public Hunter** (VK wall API, RSS, ручной Telegram); эти источники по-прежнему работают отдельно.

Оценки Company Hunter — **приоритет ручной проверки HTML**, а не прогноз конверсии или доказательство устаревшего дизайна. Публикации, результаты поиска и бизнес-сообщества требуют подтверждения актуальности. Отсутствие сайта в карточке не доказывает его отсутствия. Веб-дизайн и мобильная верстка пока не анализируются визуально.

Подробности, источники и ограничения: [docs/company-hunter-v0.8.md](docs/company-hunter-v0.8.md).

# VOID LEADS v0.4.0 — Windows EXE + обновления

### Статус сборки

- Исходный проект **готов для сборки Windows `.exe`**. В текущей Linux-среде реальный Windows EXE не компилировался и не тестировался.
- Официальная сборка на Windows происходит автоматически в **GitHub Actions (windows-latest)** с помощью PyInstaller и Inno Setup.
- Настроено обновление из GitHub Releases (отдельный `VOID-Updater.exe`). Обновление работает **после подключения публичного репозитория с выпусками** и установки первого выпущенного инсталлятора. Без репозитория кнопка корректно сообщает, что канал не настроен.
- 41 локальный тест пройден, включая тесты обновлений и резервной копии базы.

## Как выглядит жизнь после первой настройки

Один раз скачиваешь **VOID-Leads-Setup.exe** из раздела Releases своего GitHub-репозитория и устанавливаешь программу в `%LOCALAPPDATA%\Programs\VOID LEADS`. На рабочем столе появится ярлык. Python на компьютере больше не требуется.

В дальнейшем: **Настройки → Проверить обновления → Установить**. Программа скачивает новый установщик из того же заранее настроенного репозитория, сверяет SHA-256, закрывается, создаёт резервную копию БД, обновляется и запускается вновь. Публикации VK, CSV и CRM остаются в `%USERPROFILE%\VOID-LEADS\leads.sqlite3`.

## Первая сборка и подключение обновлений (рекомендуется)

Необходимо один раз создать **отдельный публичный GitHub-репозиторий**, например `void-leads`, и загрузить туда исходники из этого пакета. Не загружай в GitHub свои базы клиентов, пароли и VK-токены. Все они должны оставаться на компьютере. Если используешь GitHub Desktop, можно создать репозиторий через его интерфейс; либо в терминале из корня проекта:

```powershell
git init
git add .
git commit -m "VOID LEADS v0.4.0"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/void-leads.git
git push -u origin main
git tag v0.4.0
git push origin v0.4.0
```

Репозиторий на GitHub нужно создать **до** `git push`, команды `git remote add origin` использовать с реальным логином. Если репозиторий уже содержит коммиты, потребуется обычная синхронизация Git.

Автоматический процесс `.github/workflows/windows-release.yml` выполняет следующее:

1. Тестирует Python-приложение.
2. Встраивает в бинарник имя **именно этого GitHub-репозитория** как официальный канал обновлений.
3. Компилирует `VOID-Leads.exe` и `VOID-Updater.exe` на Windows.
4. Собирает единый установщик `VOID-Leads-Setup.exe` через Inno Setup.
5. Публикует установщик и `SHA256SUMS.txt` на странице Releases (для тега `v0.4.0`).

После успешной сборки открой `https://github.com/ТВОЙ_ЛОГИН/void-leads/releases/latest`, скачай только `VOID-Leads-Setup.exe` и установи. Выпуски могут быть доступны лишь если Actions разрешено публиковать релизы (`contents: write`).

### Для каждой следующей версии

Изменения кода публикуются в репозиторий, после чего создаётся новый тег, например `v0.4.1`:

```powershell
git add .
git commit -m "VOID LEADS 0.4.1"
git push
git tag v0.4.1
git push origin v0.4.1
```

После успешного Actions-релиза внутри установленного приложения появится обновление. **Обновление не возникает только от изменения локальных файлов:** сначала нужно опубликовать новый выпуск.

## Сборка вручную на своём Windows (без GitHub)

Запусти `build_windows.bat`, если Python уже установлен. Скрипт установит PyInstaller и создаст два EXE в папке `dist/`. Они запускаются без Python. Для удобного установщика требуется Inno Setup 6 и компиляция `installer/void-leads.iss` (или используй GitHub Actions).

**Важно:** у самостоятельно собранного EXE без публикации и встроенного адреса релизов **пока нет рабочего канала автообновлений**. Для него лучше пройти процесс через GitHub Actions.

## Безопасность и резервирование

- Обновления разрешены **только** из репозитория, встроенного во время сборки, по HTTPS. Не поддерживается произвольный URL файла EXE, присланный через браузер.
- SHA-256 сверяется с `SHA256SUMS.txt` того же GitHub Release. Это защищает от случайных повреждений, но не заменяет цифровую подпись издателя: безопасность самого репозитория и аккаунта обязательна.
- При каждом обновлении SQLite копируется в `%USERPROFILE%\VOID-LEADS\backups`; сохраняются последние пять копий.
- Ошибки установки сохраняются в `%USERPROFILE%\VOID-LEADS\updater.log`. Если включён SmartScreen, неподписанные EXE могут вызывать предупреждения Windows. Не отключай защиту Windows ради установки неизвестного файла.
- Программа не отправляет рекламный спам и не обходит ограничения пабликов; источники VK/RSS работают прежним разрешённым способом.
- Проверка GitHub Releases требует интернета и **публичных** релизов. Для приватного репозитория анонимный автообновлятор в этой версии не предусмотрен.

## Структура

- `app.py`, `engine.py`, `public_hunter.py` и остальные исходники: рабочий локальный сервер и поиск лидов.
- `static/`: светлый стеклянный интерфейс синий `#4F7CFF`.
- `release_config.py`: версия и имя репозитория (встраиваются в CI автоматически).
- `updates.py`: безопасная проверка GitHub Releases.
- `updater.py`: загрузка, проверка, копирование БД, запуск инсталлятора.
- `installer/void-leads.iss`: установщик и ярлык на рабочем столе.
- `.github/workflows/windows-release.yml`: автоматическая Windows-сборка и публикация.
- `build_windows.bat`: локальная сборка EXE на Windows.
- `tests/`: офлайн-тесты (`python -m pytest -q`).

Исходные функции v0.3.2 (Public Hunter, CSV пабликов, свежесть 24ч, карты OSM, лиды CRM) сохранены. Дополнительное ТЗ — `SPEC.md`.


## v0.5.0 — отсев новостей и диагностика источников

- Public Hunter не отправляет новости о происшествиях, статистике заболеваний и обычные сообщения городских СМИ в основную рекламную ленту. Даже если VK пометил новостной пост как рекламный.
- Основной фильтр требует коммерческое предложение и признаки обращения к покупателю. Это консервативная проверка: часть настоящих объявлений может быть ошибочно отсеяна.
- **Отсеяно фильтром**: сохранены только несколько свежих примеров для ручной проверки; кнопка «Это реклама · вернуть» добавляет найденное обратно в ленту и сохраняет решение пользователя.
- Старые неверно отобранные посты автоматически перепроверяются при первом запуске, **CRM и заметки не меняются**.
- На каждой карточке источника: число проверенных постов, распознанной рекламы, отсеянных сообщений и новых рекламных публикаций. Источник с нулевым результатом рекомендуем заменить/поставить на паузу, но не отключаем автоматически.
- Окно актуальности остаётся **24 часа**, горячие — **2 часа**, проверки при запущенной программе — **20 минут** при разрешённом доступе.
- Пример CSV дополняют тематические VK-сообщества услуг в Рязани и Твери; соответствие и доступность ещё нужно проверить на реальных стенах.

**Как проверить:** в установленном приложении обновиться через Настройки → Проверить обновления; Public Hunter → Проверить на одном паблике. Посмотреть показатели и «Отсеяно фильтром». Сравнить 10–20 постов с VK вручную, отметить ложные пропуски кнопкой восстановления. Отдельно проверить источники `bizrzn` и `club198152989` после повторного импорта CSV — существующие источники не дублируются.

Ограничения: без авторизованного VK API нельзя подтвердить выдачу реальной стены; классификатор эвристический, не гарантирует отсутствие ошибок; он не проверяет наличие сайта бизнеса автоматически и не рассылает сообщения.


## v0.6.0 — Windows Desktop / работа в фоне

### Что изменено
- Своя иконка в EXE, ярлыке, установщике и системном трее. Генерируется в CI из исходных фигур (`packaging/make_icon.py`).
- Программа остаётся активной при закрытии окна браузера. В системном трее: открыть / полностью выйти.
- Уведомления Windows о **новых** свежих рекламных публикациях с оценкой не ниже 55/100 (порог по умолчанию). Старые и повторно увиденные публикации не оповещаются. Уведомления зависят от разрешений Windows и доступности системного трея.
- В настройках: фоновый режим и уведомления, тестовое уведомление, добровольный автозапуск с Windows (не включается автоматически).
- VK-токен теперь можно однократно сохранить кнопкой «Сохранить ключ на этом ПК»; в Windows используется DPAPI, расшифровка доступна только текущему пользователю. Токен не попадает в GitHub, SQLite, CSV или журнал. Можно удалить отдельной кнопкой. Сохранение доступно только в Windows. После обновления впервые нужно сохранить ключ вручную.
- Приветствие «Данил» в обзоре и тестовом уведомлении.
- Интервал ручной повторной проверки одного источника — 60 секунд **с момента начала предыдущей попытки**, сообщение об ошибке показывает сколько осталось. Старые источники с 20-минутным интервалом при первой миграции переключаются на 1 минуту. Много источников опрашиваются последовательно, **точно раз в минуту для каждого** при большой базе не гарантируется: учитываются квоты VK, ограничения RSS и время ответа.
- Public Hunter: фильтр рекламных публикаций по конкретному источнику (отдельно от фильтра свежести). Выбор сохраняется при смене типа ленты и обновлении данных.
- Защита от повторного запуска второго сервера при наличии работающего экземпляра в системном трее.
- Светлая стеклянная тема сохранена.

### Проверка на своём Windows
1. Обновись через Настройки → Проверить обновления.
2. Public Hunter → вставь свой сервисный VK-токен → «Сохранить ключ на этом ПК». Никому его не отправляй.
3. Настройки → нажми «Проверить уведомление». Если ничего нет, проверь «Не беспокоить» и разрешение уведомлений Windows.
4. По желанию включи «Запускать с Windows».
5. Закрой окно браузера (не выбирай «Выйти из программы» в трее): значок VOID LEADS должен оставаться в области уведомлений, проверка источников продолжаться.
6. Проверь один паблик; повторная ручная проверка доступна через 60 секунд. В разделе «Рекламные публикации» выбери один источник в выпадающем фильтре.
7. Перезагрузи программу и проверь, что сохранённый токен остался. При запуске другого пользователя Windows сохранённый токен не расшифруется.

Важные ограничения: уведомления требуют работающего приложения и действующих прав доступа к источникам, это не облачный мониторинг; когда ПК выключен, спит или нет сети, проверка не выполняется. Windows SmartScreen может предупреждать о неподписанной сборке. Автоматического чтения закрытых Telegram-чатов и массовой рассылки по-прежнему нет.


## v0.6.1 — диагностика старых отклонённых постов

Сценарий реального теста: из 24 опубликованных постов 23 не содержали коммерческих предложений, 1 была настоящей рекламой за прошлую неделю. Ранее `Отсеяно: 23` отображалось в диагностике, но старые отклонения не сохранялись в базе, поэтому очередь была пустой. При этом реклама корректно попадала в архив, а новых лидов было ноль.

Теперь:
- Каждый отклонённый при проверке пост **включая старые** сохраняется в отдельной очереди для ручной проверки; повторные проверки не создают дубли.
- Очередь отсортирована по времени обнаружения, а не по дате публикации; видны старые рекламные тексты, которые программа могла пропустить.
- Числа `Отсеяно` (всего за последнюю проверку) и `В очереди` (доступных на ручной разбор) показаны отдельно; `В архиве` отражает старую распознанную рекламу.
- В карточке паблика добавлена кнопка `Разобрать N`, открывающая его отсеянные публикации.
- Диагностические отсеянные посты удаляются через 7 дней **после обнаружения**, а их общее количество ограничено 3000. Подтверждённые лиды и вручную восстановленные публикации не очищаются этим правилом.
- Если восстановленная публикация старше 24 часов, программа сразу открывает **Архив**, а не пытается показать её в свежей ленте.
- Предыдущие несохранённые записи нельзя восстановить локально; после обновления нужно повторно проверить паблик через VK API, чтобы программа получила и сохранила их.

Проверка Windows CI: 24 фиктивные VK-публикации (1 коммерческая, 23 старые новости), затем повторный запрос и проверка отсутствия дублей.


## VOID LEADS v0.7.1 — Public Hunter UI & Seamless Updates

### Фильтры
- Новая адаптивная светлая стеклянная панель для источника, периода, ниши и переключателя «Только перспективные».
- Настройка приоритетных ниш раскрывается отдельно: крупные контрастные чипы, счётчик и кнопка сохранения.
- Смена разделов больше не сбрасывает период Public Hunter; раскрытая панель не закрывается от фонового обновления списка.
- Исправлен конфликт одинаковых HTML id между фильтром источника и формой ручного добавления публикации.
- Изменения не затрагивают логику распознавания рекламы или данные CRM.

### Установка обновления
- Сначала внешний обновлятор скачивает файл из официального GitHub Release и проверяет SHA-256.
- Пока идёт загрузка, запущенный VOID LEADS остаётся доступным. При ошибке скачивания или проверки старая программа не закрывается.
- После скачивания создаётся резервная копия SQLite; только затем проверенный обновлятор подаёт защищённый локальный сигнал на завершение старого процесса.
- Установщик ждёт закрытия предыдущего EXE, обновляет программу и запускает новую версию.
- Отображается светлый экран обновления со статусами и сообщениями об ошибках.
- Новая Windows-версия открывает собственное Edge/Chrome app-окно в изолированном профиле, чтобы при закрытии программы не затрагивать чужие вкладки браузера.

**Ограничение первой миграции:** обновление с v0.7.0 запускает ещё старый обновлятор, который не умеет закрывать его окно целенаправленно. При переходе на v0.7.1 первое старое окно может потребовать ручного закрытия. Начиная с новой версии используется обновлённая схема управления окном; поведение на пользовательской Windows-машине необходимо подтвердить тестом.

**Безопасность:** сохраняются локальные данные, VK-токен под Windows DPAPI и настройки. Обновление не отключает SmartScreen, не закрывает сторонние браузеры и не требует копировать пароли в GitHub.

### Тест-план
1. Public Hunter: источник, период, ниша и переключатель независимо меняют выборку.
2. Настройка ниш: сохранить / открыть снова / сменить раздел / перезапустить программу.
3. Ширины 390, 768, 1200, 1440 и 1920 px; никаких обрезаний и горизонтального скролла панели.
4. Настройки: проверить новую версию; установка открывает прогресс без немедленного отключения поиска.
5. При доступном релизе: скачать, проверить SHA, создать backup, закрыть старый EXE, установить и открыть новую версию.
6. При неподходящей контрольной сумме или обрыве сети: старая версия остаётся открытой.
