# VOID LEADS v0.4.0 — Windows EXE + обновления

### Статус сборки

- Исходный проект **готов для сборки Windows `.exe`**. В текущей Linux-среде реальный Windows EXE не компилировался и не тестировался.
- Официальная сборка на Windows происходит автоматически в **GitHub Actions (windows-latest)** с помощью PyInstaller и Inno Setup.
- Настроено обновление из GitHub Releases (отдельный `VOID-Updater.exe`). Обновление работает **после подключения публичного репозитория с выпусками** и установки первого выпущенного инсталлятора. Без репозитория кнопка корректно сообщает, что канал не настроен.
- 41 локальный тест пройден, включая тесты обновлений и резервной копии базы.

## Как выглядит жизнь после первой настройки

Один раз скачиваешь **VOID-Leads-Setup.exe** из раздела Releases своего GitHub-репозитория и устанавливаешь программу в `%LOCALAPPDATA%\Programs\VOID LEADS`. На рабочем столе появится ярлык. Python на компьютере больше не требуется.

В дальнейшем: **Настройки → Проверить обновления → Установить**. Программа скачивает новый установщик из того же заранее настроенного репозитория, сверяет SHA-256, закрывается, создаёт резервную копию БД, обновляется и запускается вновь. Публикации VK, CSV и CRM остаются в `%USERPROFILE%\VOID-LEADS\leads.sqlite3`.

## Первая сборка и подключение обновлений (рекомендуется)

Необходимо один раз создать **отдельный публичный GitHub-репозиторий**, например `void-leads`, и загрузить туда исходники из этого пакета. Не загружай в GitHub свои базы клиентов, пароли и VK-токены. Все они должны оставаться на компьютере. Если используешь GitHub Desktop, можно создать репозиторий через его интерфейс; либо в терминале из корня проекта:

```powershell
git init
git add .
git commit -m "VOID LEADS v0.4.0"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/void-leads.git
git push -u origin main
git tag v0.4.0
git push origin v0.4.0
```

Репозиторий на GitHub нужно создать **до** `git push`, команды `git remote add origin` использовать с реальным логином. Если репозиторий уже содержит коммиты, потребуется обычная синхронизация Git.

Автоматический процесс `.github/workflows/windows-release.yml` выполняет следующее:

1. Тестирует Python-приложение.
2. Встраивает в бинарник имя **именно этого GitHub-репозитория** как официальный канал обновлений.
3. Компилирует `VOID-Leads.exe` и `VOID-Updater.exe` на Windows.
4. Собирает единый установщик `VOID-Leads-Setup.exe` через Inno Setup.
5. Публикует установщик и `SHA256SUMS.txt` на странице Releases (для тега `v0.4.0`).

После успешной сборки открой `https://github.com/ТВОЙ_ЛОГИН/void-leads/releases/latest`, скачай только `VOID-Leads-Setup.exe` и установи. Выпуски могут быть доступны лишь если Actions разрешено публиковать релизы (`contents: write`).

### Для каждой следующей версии

Изменения кода публикуются в репозиторий, после чего создаётся новый тег, например `v0.4.1`:

```powershell
git add .
git commit -m "VOID LEADS 0.4.1"
git push
git tag v0.4.1
git push origin v0.4.1
```

После успешного Actions-релиза внутри установленного приложения появится обновление. **Обновление не возникает только от изменения локальных файлов:** сначала нужно опубликовать новый выпуск.

## Сборка вручную на своём Windows (без GitHub)

Запусти `build_windows.bat`, если Python уже установлен. Скрипт установит PyInstaller и создаст два EXE в папке `dist/`. Они запускаются без Python. Для удобного установщика требуется Inno Setup 6 и компиляция `installer/void-leads.iss` (или используй GitHub Actions).

**Важно:** у самостоятельно собранного EXE без публикации и встроенного адреса релизов **пока нет рабочего канала автообновлений**. Для него лучше пройти процесс через GitHub Actions.

## Безопасность и резервирование

- Обновления разрешены **только** из репозитория, встроенного во время сборки, по HTTPS. Не поддерживается произвольный URL файла EXE, присланный через браузер.
- SHA-256 сверяется с `SHA256SUMS.txt` того же GitHub Release. Это защищает от случайных повреждений, но не заменяет цифровую подпись издателя: безопасность самого репозитория и аккаунта обязательна.
- При каждом обновлении SQLite копируется в `%USERPROFILE%\VOID-LEADS\backups`; сохраняются последние пять копий.
- Ошибки установки сохраняются в `%USERPROFILE%\VOID-LEADS\updater.log`. Если включён SmartScreen, неподписанные EXE могут вызывать предупреждения Windows. Не отключай защиту Windows ради установки неизвестного файла.
- Программа не отправляет рекламный спам и не обходит ограничения пабликов; источники VK/RSS работают прежним разрешённым способом.
- Проверка GitHub Releases требует интернета и **публичных** релизов. Для приватного репозитория анонимный автообновлятор в этой версии не предусмотрен.

## Структура

- `app.py`, `engine.py`, `public_hunter.py` и остальные исходники: рабочий локальный сервер и поиск лидов.
- `static/`: светлый стеклянный интерфейс синий `#4F7CFF`.
- `release_config.py`: версия и имя репозитория (встраиваются в CI автоматически).
- `updates.py`: безопасная проверка GitHub Releases.
- `updater.py`: загрузка, проверка, копирование БД, запуск инсталлятора.
- `installer/void-leads.iss`: установщик и ярлык на рабочем столе.
- `.github/workflows/windows-release.yml`: автоматическая Windows-сборка и публикация.
- `build_windows.bat`: локальная сборка EXE на Windows.
- `tests/`: офлайн-тесты (`python -m pytest -q`).

Исходные функции v0.3.2 (Public Hunter, CSV пабликов, свежесть 24ч, карты OSM, лиды CRM) сохранены. Дополнительное ТЗ — `SPEC.md`.


## v0.5.0 — отсев новостей и диагностика источников

- Public Hunter не отправляет новости о происшествиях, статистике заболеваний и обычные сообщения городских СМИ в основную рекламную ленту. Даже если VK пометил новостной пост как рекламный.
- Основной фильтр требует коммерческое предложение и признаки обращения к покупателю. Это консервативная проверка: часть настоящих объявлений может быть ошибочно отсеяна.
- **Отсеяно фильтром**: сохранены только несколько свежих примеров для ручной проверки; кнопка «Это реклама · вернуть» добавляет найденное обратно в ленту и сохраняет решение пользователя.
- Старые неверно отобранные посты автоматически перепроверяются при первом запуске, **CRM и заметки не меняются**.
- На каждой карточке источника: число проверенных постов, распознанной рекламы, отсеянных сообщений и новых рекламных публикаций. Источник с нулевым результатом рекомендуем заменить/поставить на паузу, но не отключаем автоматически.
- Окно актуальности остаётся **24 часа**, горячие — **2 часа**, проверки при запущенной программе — **20 минут** при разрешённом доступе.
- Пример CSV дополняют тематические VK-сообщества услуг в Рязани и Твери; соответствие и доступность ещё нужно проверить на реальных стенах.

**Как проверить:** в установленном приложении обновиться через Настройки → Проверить обновления; Public Hunter → Проверить на одном паблике. Посмотреть показатели и «Отсеяно фильтром». Сравнить 10–20 постов с VK вручную, отметить ложные пропуски кнопкой восстановления. Отдельно проверить источники `bizrzn` и `club198152989` после повторного импорта CSV — существующие источники не дублируются.

Ограничения: без авторизованного VK API нельзя подтвердить выдачу реальной стены; классификатор эвристический, не гарантирует отсутствие ошибок; он не проверяет наличие сайта бизнеса автоматически и не рассылает сообщения.
