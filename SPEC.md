# VOID LEADS v0.3.2 — зафиксированное ТЗ

## Назначение
Личный локальный Windows-инструмент для поиска потенциальных заказчиков веб-разработки и автоматизаций по сигналам из местной рекламы и пабликов, без спама и конкуренции на массовых фриланс-биржах.

## Дизайн
Сохранить удачную концепцию v0.2: светлая минималистичная тема в духе Apple, glassmorphism, один синий акцент `#4F7CFF`, минимальные эффекты, увеличенные читаемые шрифты, адаптивный интерфейс на 1440+, 1200 и малых окнах. Панели не обрезаются, длинные списки имеют прокрутку.

## Модули
1. **Public Hunter:** каталог пабликов, поиск по источникам, проверка, отдельные очереди свежих, архивных и без даты, просмотр оригинала, ручной отбор в CRM.
2. **AD Hunter:** захват публикации вручную и повторной рекламы, извлечение контактов.
3. **Map Hunter:** текущий ограниченный поиск OSM, без массового копирования данных Яндекс Карт.
4. **CRM:** компании, контакты, статусы, история, черновики, сделки.
5. **Source Manager:** добавление, приостановка, импорт CSV и антидубли.

## Правила свежести
- По умолчанию основной экран показывает посты возрастом **не более 24 часов** по времени первоначальной публикации.
- Первые **2 часа** — приоритет «горячее».
- Более **24 часов** — архив, не показывать в основной ленте.
- Без валидной даты и с неверной датой (в том числе неожиданно будущей) — очередь «Без даты», не считать свежей.
- Дедуплицировать по паре `(source_id, external_id)`; архив не удалять автоматически, нужен для анализа повторных публикаций.
- Нельзя подменять дату публикации временем получения программой.
- Если компания перенесена в CRM, её не удалять при старении объявления.

## Интеграция пабликов
- VK: только официальный `wall.get`, легитимный токен; последние до 100 постов; при доступном флаге `marked_as_ads` учитывать его.
- RSS/Atom: только публичные HTTPS фиды, ограничение размера и редиректов, безопасная работа с XML.
- Telegram: ручной ввод текста и исходной ссылки; автоматическое чтение незнакомых чатов не входит в MVP.
- Фоновая проверка: рекомендуемый интервал **20 минут**, индивидуальная настройка **15–180 минут**. Пока локальное приложение открыто; последовательный опрос может отставать при большом числе источников.
- Секрет VK не сохранять на диск, использовать только в памяти приложения или локально управляемой переменной окружения.
- Показывать последнюю удачную проверку, ошибку и число свежих публикаций для источника.

## CSV
- Отдельные импорты: **список пабликов** и **список компаний**.
- Источники: `Название;Город;Тип;Адрес;Активен;Интервал`, русские или английские заголовки, CSV UTF-8/UTF-8 BOM, разделитель `;`, `,` или TAB.
- Типы: VK, RSS, Telegram (manual).
- Нормализация VK URL в короткое имя, безопасная валидация RSS/Telegram URL; антидубли.
- Частичные ошибки не должны терять корректные строки. Импорт должен возвращать созданные, дубликаты и ошибочные строки.
- Подготовить отдельный кандидатный CSV с реальными публично идентифицированными сообществами и ссылками на источники их подтверждения в документации.

## Тестирование и критерии готовности
- Локальные API-тесты и UI-проверка размеров 1440/1200/390.
- Тесты дат +2ч, 0ч, 3ч, 24+ч, 30ч, RFC822, ISO UTC, неопределённой даты.
- Тест импорта реального списка 9 пабликов; повторный импорт не создаёт дублей.
- Миграция предыдущей SQLite БД без потери данных.
- На фиктивном VK-ответе проверить работу автообновления и антидублей, без выдачи тестовых лидов за реальные.
- Для реального VK smoke test пользователь должен иметь собственный легитимный API ключ. Не утверждать, что реальные посты загружены, до проверки на живой площадке.

## Коммерческий тест после установки
Первые 7 дней следить за 5–10 городскими пабликами из списка кандидатов. Метрика не число собранных постов, а число квалифицированных компаний, сайтов с проблемами и законных способов начать диалог. Исключать шумные паблики, где рекламодателей почти нет.

## Ограничения
Нет автоспама, обхода технических ограничений, скрытого сбора чатов Telegram, гарантированной полноты публикаций и ложных заявлений о наличии/отсутствии сайтов.


## Исправление VK v0.3.2
- Устранить ложное сообщение «Ответ VK превышает лимит» из-за прежнего жёсткого потолка в 500 КБ на 100 публикаций.
- Загружать `wall.get` небольшими страницами (25 элементов), при слишком большой странице повторять **тот же offset** с меньшим count (10/5/1).
- Ограничивать ответ 3 МБ на страницу, чтение максимум 100 постов за проверку и делать паузу между запросами, чтобы не создавать чрезмерную нагрузку на API.
- Прекращать историческую выгрузку, когда последние обычные записи в странице старше 24 часов; закреплённые записи не должны преждевременно прерывать выгрузку.
- Различать ошибку VK 6 (частота API) и внутреннее ограничение размера ответа.
- Не менять структуру БД, цветовую тему, типографику и остальные рабочие функции.

## Дополнение v0.4.0: установщик и автообновления

**Цель:** прекратить передачу ZIP при каждом изменении. Использовать одну установленную Windows-программу и управляемый канал релизов.

1. Клиент — Windows 10/11, основной `VOID-Leads.exe`, локальный HTTP интерфейс в окне Edge/Chrome, никаких ручных вызовов Python.
2. Установка — `VOID-Leads-Setup.exe` (Inno Setup, установка без прав администратора в LocalAppData, ярлык).
3. Сборка — Windows GitHub Actions по тегу версии `vX.Y.Z`; PyInstaller `--onefile` для приложения и независимого обновлятора. Установщик и SHA256SUMS публикуются вместе.
4. Проверка — экран «Настройки», кнопка проверки версии и кнопка установки. Источник — единственный доверенный GitHub Releases репозиторий, который встраивается в EXE на стадии сборки.
5. Установка — обновлятор скачивает EXE, сравнивает SHA-256, ожидает завершения приложения, создаёт резервную копию SQLite, устанавливает выпуск Inno Setup и перезапускает программу.
6. Хранение — база `%USERPROFILE%\VOID-LEADS\leads.sqlite3` вне папки бинарников, не удаляется при обновлении. Хранить последние пять копий в `backups`.
7. Ограничения — неподписанная сборка может вызывать SmartScreen; канал требует публичного GitHub Releases и не работает до первой официальной публикации. Подлинность автора следует дополнительно обеспечивать защитой GitHub-аккаунта, а в будущем — подписью установщика.
8. Сохранить прежний светлый glass UI, типографику, логику свежих постов VK/RSS/ручного Telegram, CSV источников и все поля CRM.

**Состояние:** код обновлений и Windows CI добавлены, локальные тесты пройдены. Установщик Windows на текущем Linux-хосте не скомпилирован и на пользовательском компьютере не проверен.
